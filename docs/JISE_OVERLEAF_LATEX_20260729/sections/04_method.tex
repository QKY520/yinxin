\section{METHOD}

\subsection{Proposed EC-FSIE Framework}

Evidence-Controlled Few-Shot Information Extraction (EC-FSIE) organizes
low-label extraction as a closed evidence-and-execution contract rather than a
loose collection of prompt additions. For a query $x$ and schema $S$, the local
extractor receives a prompt formed from three explicit evidence channels:
retrieved demonstrations $\mathcal{D}_K(x)$, matched glossary entries
$\mathcal{G}(x)$, and reranked passages $\mathcal{R}(x)$. An execution layer
$\mathcal{A}$ then parses and records the prediction:
\[
\hat{Y},\tau = \mathcal{A}\!\left(f_{\theta}\!\left(
P\!\left(S,\mathcal{D}_K(x),\mathcal{G}(x),\mathcal{R}(x),x\right)
\right)\right),
\]
where $P$ is the fixed-order prompt constructor, $f_{\theta}$ is the locked
local extractor, and $\tau$ denotes the request, cache, retry, parser, and
output trace. Each
channel is controlled by provenance, bounded injection, leakage-safe resource
construction, and deterministic replay. Semantic retrieval selects
query-relevant demonstrations; the schema-specific glossary contributes compact
terminology; and reranked RAG supplies contextual evidence. Deterministic
parsing, retry logging, hash-based caching, and per-query records make the
result traceable. The A/B/C/D chain in Table~\ref{tab:configs} exposes the three
evidence channels incrementally, while the common execution contract governs
every configuration. This design connects observed metric changes to a named
control surface without sacrificing end-to-end auditability.

\subsection{Structured Few-Shot Extraction}

The NER instantiation of EC-FSIE receives one query passage and $K$ support
examples and returns a JSON entity list. Prompt blocks follow a fixed order:
task definition, entity schema, optional glossary entries, optional RAG
evidence, $K$ demonstrations, and the query passage. This order keeps schema,
external evidence, demonstrations, and the evaluation query structurally
separable. The output instruction requires JSON only. Requests are
cached by a SHA256 hash of the complete prompt and model-relevant generation
settings. The parsing ladder strips code fences, attempts structured JSON
parsing, retries once with a legal-JSON reminder when necessary, and records a
second failure as no prediction while preserving the raw output.
All reported NER runs use temperature 0.0, top-$p$ 1.0, a 768-token output
limit, and the recorded run seed. Exact-hash cache hits replay the identical
request result and are audit events rather than an additional source of
randomness.

\subsection{Demonstrations, Glossary, and RAG Evidence}

In fixed-random mode, one $K$-example set is selected from the support split
according to the run seed. In kNN mode, BGE-M3 \cite{chen2024m3} encodes
normalized support and query vectors, and FAISS inner-product search retrieves
the $K$ most similar support examples for each query. For configurations C and
D, the retrieved example identifiers are replayed from configuration B so that
B-to-C and C-to-D comparisons isolate glossary and RAG changes, respectively.

For the equipment-domain block, the glossary is seeded from project-recorded
QAonMilitaryKG terminology and high-frequency corpus terms. Entries are
matched to a query by substring or keyword, with at most 20 injected entries.
The equipment-domain RAG corpus is segmented into 260-character chunks with a
40-character overlap and a maximum injected passage length of 300 characters.
Normalized BGE-M3 vectors and a FAISS inner-product index first retrieve the
top 20 candidates; \modelname{bge-reranker-v2-m3} reranks them, and the top 3
evidence passages are inserted into the prompt. Embedding and reranking use the
locked CPU path. RAG evidence constrains extraction during generation.

For CLUENER, the same module interfaces are instantiated with independently
frozen, schema-specific resources: a 30-record support bank, a 61-entry
support-derived lexicon, and a labels-stripped 9,584-row CLUENER train-text RAG
pool. The top-3 selections are replayed from a frozen 1,343-row/4,029-passage
retrieval artifact. Consequently, the public comparison instantiates the same
EC-FSIE interfaces under the native CLUENER schema while preserving strict
separation from the equipment glossary and equipment-domain evidence corpus. It
tests directional recurrence of the controls, not transfer of domain resources.
