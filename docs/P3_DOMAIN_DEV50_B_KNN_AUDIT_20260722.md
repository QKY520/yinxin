## 三、B 为什么低于 A —— 三个根因

### 根因 1：kNN 示例子领域错配

**最差案例 domain-candidate-0139**（乌克兰无人战斗直升机，A=0.769 → B=0.143，−0.626）：

- Query: 无人战斗直升机，携带非制导火箭弹/精确制导弹药/反坦克导弹/机枪
- B 的 kNN: 苏-34 战斗机、无人机火控系统（不同概念）、台风战斗机空空导弹测试、S-400 防空系统、EL/M-2084 雷达
- **零个示例与"武器载荷清单型"文本匹配**

结果：B 将 4 个 MODULE（非制导火箭弹/精确制导弹药/反坦克导弹/机枪）全部错标为 EQUIPMENT。kNN 示例中的标注风格（news 文本以 EQUIPMENT 为主）诱导模型将武器组件提升为独立装备。

**最差案例 domain-candidate-0218**（S-400 系统描述，A=0.824 → B=0.308，−0.516）：

- Query: 列举 S-400 打击的目标类型（远程空中预警机、空中指挥点、电子战飞机、战略轰炸机、弹道目标）
- B 的 kNN: S-400（同一系统但不同文本）、F/A-18 吊舱、精确制导弹药、海德拉火箭弹、M1200 装甲车
- kNN 中仅 1 条与 query 直接相关，其余 4 条是不同的装备子领域

结果：B 仅输出 4 个实体（A 输出 8 个），遗漏 4 个目标类型（远程空中预警机/空中指挥点/电子战飞机/战略轰炸机），转而过度关注 METRIC（"4800米/秒""24公斤"）。

### 根因 2：类型分布被 kNN 示例扭曲

| 类型 | A | B | Δ | 分析 |
|------|---|---|----|------|
| METRIC | 17 | **34** | **+100%** | kNN 示例含大量指标型实体（重量/射程/口径），诱导模型 eager-metric |
| TECH_SCHEME | 11 | **22** | **+100%** | kNN 示例含较多 TECH_SCHEME（制导体制/技术方案），模型学到过标 |
| MODULE | 138 | **116** | **−16%** | 部分 MODULE 被错标为 EQUIPMENT 或 METRIC |

30 条 support 的类型分布不均衡（某些行 METRIC/TECH_SCHEME 密集），kNN 放大了这个偏差。A 的固定示例类型分布更均匀。

### 根因 3：Support 池 30 条不足以支撑 K=5 kNN

30 条 support 覆盖了 baidu_baike(3)、patent(8)、cmnee(19) 三种格式，50 条 dev 同样覆盖这三种格式。K=5 意味着每条 query 从 30 条中选 5 个最近邻——去除自身后实际候选约 29 条。

当 query 是专利格式但 support 中只有 8 条专利时，kNN 很容易拉入 cmnee 新闻文本作为"最近邻"——BGE-M3 的语义空间里，"装备"关键词的相似度高于"专利格式"的结构相似度。结果是模型看到的示例**格式不匹配**（新闻示例用于专利 query，或军事示例用于民用专利 query）。

**B 改善的 12 条案例**中的 pattern：这些 query 碰巧从 30 条 support 中检索到了真正同子领域的示例。例如 domain-candidate-0015（无人飞行器专利）的 kNN 包含 domain-candidate-0010（穿戴式无人机控制专利）——正确匹配了"无人机+专利"两个维度。

### 根因总结表

| 根因 | 严重度 | 影响的 rows（估计） |
|------|--------|-------------------|
| kNN 子领域错配（军事 vs 民用、平台 vs 弹药） | 🔴 高 | ~15 worse |
| 类型分布扭曲（METRIC/TECH 翻倍） | 🟡 中 | 全局 |
| Support 池太小（30→K=5 时降级为随机） | 🔴 高 | 全局 |

## 六、判断

| 问题 | 回答 |
|------|------|
| kNN 示例是否靠谱？ | **不靠谱。** 30 条 support 配 K=5，BGE-M3 浅层语义匹配不足以隔离子领域和文本格式。15/50 条显著退化 |
| B 是否值得继续用？ | **当前形式不值得。** 需要先扩大 support 池或改进检索策略 |
| Sanitization 是否仍可靠？ | **是。** 32 flags 全部正确，0 误删 |
| 下一步？ | **保留 B 为负结果，不阻塞管道。建议跳 B 直接试 C (glossary injection)** |

### 关于 C (glossary) 的理由

Glossary 不依赖 embedding 相似度，而是基于术语精确匹配。装备 domain 的术语表（QAonMilitaryKG 种子）可以直接帮助模型识别正确的实体类型和边界，不受 kNN 检索质量影响。C 应比 B 更稳健。

### 长期改进 B 的路径（非阻塞）

1. Support 池扩容（≥100 条）后再试 kNN
2. 用 bge-reranker-v2-m3 对 FAISS top-20 重排后取 top-5
3. 混合检索：固定 2-3 个跨格式示例 + kNN 补 2-3 个
4. BM25 关键词检索作为 embedding 检索的补充
