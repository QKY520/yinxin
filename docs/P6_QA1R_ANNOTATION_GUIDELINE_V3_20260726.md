# P6-QA1R 装备领域 NER 标注指南 v3

日期：2026-07-26

状态：用于非 test 校准；尚未批准用于正式 test 重标

任务范围：仅 NER，不标关系

## 1. 核心目标

对文本中每个明确出现的实体词面，标注其 Python 字符偏移和一种实体类型：

```json
[{"start":0,"end":4,"type":"EQUIPMENT","span":"示例装备"}]
```

必须同时满足：

1. `end` 为不包含式偏移，且 `text[start:end] == span`；
2. 每个实体只有一种类型；
3. 不允许嵌套或重叠实体；
4. 按 `(start, end, type)` 升序排列；
5. 同一词面每次明确出现都分别标注；
6. 确认无实体时填写 `[]`，不得留空；
7. 不使用模型建议、旧 gold、对方结果或领域常识补标签。

## 2. 固定判定顺序

对候选短语依次回答：

1. 它是不是文本中明确出现、语义自足的名词短语？不是则不标。
2. 它是否表达“属性名称 + 数值、范围、阈值、等级或单位”？是则优先判为
   `METRIC`。
3. 它是否为物理对象、设备、平台、系统、装置或部件？是则在
   `EQUIPMENT` 与 `MODULE` 之间按当前结构角色判断。
4. 它是否为非物理的命名技术、方法、算法、体制、流程或工程方案？是则判为
   `TECH_SCHEME`。
5. 若以上均不满足，则不标，并可在 `notes` 中记录疑点。

不要依据单个后缀直接分类。例如“系统”既不能自动等于 `EQUIPMENT`，也不能自动
等于 `TECH_SCHEME`；必须先判断它是具体物理/功能系统，还是抽象方法体系。

## 3. 四类实体

### 3.1 `EQUIPMENT`

能够独立承担任务或功能的装备、武器、平台、整机、完整装置、独立部署系统或明确
型号。型号、系列号和区分该装备所必需的限定词包含在边界内。

标注：

- “苍穹-1无人机”中的完整型号与装备名称；
- 独立部署的雷达、声呐、导弹、无人机、通信终端；
- 当前句子明确把某系统作为完整任务平台时的系统名称。

不标或改判：

- “该系统”“这种装备”等代词或泛指；
- 组织、国家、地点、人员；
- 明确作为更大装备组成部分的对象，此时判为 `MODULE`；
- 功能、算法或技术方法，此时考虑 `TECH_SCHEME`。

### 3.2 `MODULE`

在当前语境中明确充当组成部分、子系统、载荷、组件、单元、部件或功能模块的物理
或功能对象。名称中含“系统”“装置”“雷达”不妨碍其在组成语境中成为模块。

常见组成信号：

- “X 的 Y”“由 Y 组成”“包括 Y”“安装 Y”“配备 Y”；
- Y 被描述为某平台内部的子系统、控制器、传感器、天线、战斗部、引信或载荷。

注意：

- “搭载/使用 Y”本身不自动证明永久组成，但若上下文明确 Y 是载荷或子系统，仍标
  为 `MODULE`；
- 含数字的组件名称仍是模块，例如“30毫米机关炮”“90g B炸药”，数字不能使其
  变成 `METRIC`；
- “数字式信号处理系统”“传感器系统”“飞行控制系统”若指具体子系统，应标
  `MODULE`，不能因具有技术含义而标成 `TECH_SCHEME`。

### 3.3 `TECH_SCHEME`

非物理、可命名的技术方法、算法、工作体制、体系结构、流程、控制律或工程方案。
它回答的是“采用什么方法/机制”，而不是“安装了什么设备/部件”。

通常标注：

- 含必要限定词的“脉冲压缩技术”“惯性导航”“自适应波束形成算法”；
- 明确命名的“解耦控制律”“频率捷变体制”；
- 能独立指代技术方法的完整名词短语。

通常不标：

- 具体传感器、控制器、装置、模块或物理系统；
- 孤立且泛化的“控制”“通信”“导航”“探测”；
- 普通动作、能力描述或完整句子；
- 仅表示工作状态、部署地点或组织方式的普通短语。

`MODULE` 与 `TECH_SCHEME` 的最小对照：

| 表达 | 类型 | 原因 |
| --- | --- | --- |
| 脉冲压缩模块 | `MODULE` | 具体功能组件 |
| 脉冲压缩技术 | `TECH_SCHEME` | 非物理方法 |
| 飞行控制系统（机内子系统） | `MODULE` | 具体组成系统 |
| 自适应飞行控制算法 | `TECH_SCHEME` | 算法 |

### 3.4 `METRIC`

能够独立表达技术规格的连续短语。边界通常包含：指标名称、比较词或上下限、数值、
单位，以及改变指标含义的紧邻工况。

标注：

- “最大探测距离不低于200公里”；
- “浅水模式下的定位误差小于5米”；
- “工作频段2.4至2.5吉赫”；
- 并列参数应分别标成多个自足指标。

不标：

- 年份、序号、普通计数；
- 型号中的数字；
- 没有属性名称的孤立数字；
- 含数字的武器或组件名称；
- “性能良好”等不可复算描述。

不得因为把握不足而整类跳过 `METRIC`。遇到共享属性、省略单位或边界不清时，先按
最短语义自足原则作出独立判断，并使用 `METRIC_SCOPE` 疑点码。

## 4. 边界规则

1. 选择“最短但语义自足”的连续 span；保留型号和改变实体身份的关键限定词。
2. 排除外围介词、所有格助词、连接词、谓词和句末标点。
3. 完整命名实体内部出现较短名称时，只保留完整长名称，不做嵌套。
4. 并列的两个自足实体分别标注，不把连接词包含在任一实体内。
5. 一个长短边界都合理时，优先保留能唯一指代对象或指标的最短完整边界，并在
   `notes` 中写 `BOUNDARY`，供校准讨论。

合成对照：

| 文本片段 | 推荐边界 |
| --- | --- |
| 采用先进的脉冲压缩技术进行处理 | `脉冲压缩技术` |
| 安装节流制冷锑化铟探测器 | `节流制冷锑化铟探测器` |
| X波段有源相控阵雷达开始工作 | `X波段有源相控阵雷达` |
| 最大航速不低于30节 | `最大航速不低于30节` |

## 5. 重复 mention 与提交前自检

若同一实体词面在文本中出现多次，每次显式出现均单独标注；后续出现即使语义相同，
也不能省略。代词不标。

每一行提交前必须完成：

1. 对每个已标 span 在全文中搜索同一词面，确认其他明确出现是否也应标注；
2. 检查 `text[start:end] == span`；
3. 检查无重复三元组、无嵌套或重叠；
4. 按 `(start,end,type)` 排序；
5. 零实体填写 `[]`；
6. 不查看另一位标注者文件。

## 6. 疑点码

校准表的 `uncertainty_code` 只能使用以下值；多个值用分号分隔：

- `TYPE_EQUIPMENT_MODULE`
- `TYPE_PHYSICAL_TECH`
- `BOUNDARY`
- `METRIC_SCOPE`
- `REPEATED_MENTION`
- `EXCLUDE_OR_TAG`
- `OTHER`

疑点码不替代标签。两位标注者仍应独立给出当前最佳判断，校准完成后再共同讨论。

## 7. 校准与正式重标协议

1. A/B 分别领取不同顺序的 24 条非 test 校准表和同一版本指南。
2. 双方独立完成第一遍，不共享脚本、词典、标签或讨论记录。
3. 协调员先做结构验证，再计算 exact `(start,end,type)` 文件一致度；该数字仅用于
   校准，不是论文 formal test IAA。
4. 双方共同讨论分歧，只修改本指南和合成示例，不把旧 test gold 或模型预测作为
   答案。
5. 校准目标建议为 exact F1 `>=0.85`，且四类均有实际覆盖；若未达到则再做一轮
   新的非 test 校准。
6. 指南锁定后，必须从全新空白 test 表开始独立重标；不得修补当前 QA2 文件。
7. 正式 test 的硬门仍为完整有效集合 exact micro-F1 `>=0.80`。通过后才能申请
   盲裁决、`v2` 冻结和统一重评分。

## 8. 红线

- 不以修改标签、删除难例、合并分歧文件或更换宽松指标来“做高”IAA；
- 不把校准协商后的相同文件称作独立标注；
- 不把当前 provenance 无效文件的 `0.5573` 称作 human IAA；
- 不覆盖 frozen `v1`；
- 不读取 A/B/C/D 预测来决定 gold；
- 不在本门禁中运行模型、dry-run、vLLM 或 paid GPU。
