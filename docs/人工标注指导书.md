# 人工标注指导书

日期：2026-07-21

## 1. 本指导书的用途

本指导书用于 P2 领域数据阶段的人工标注准备。目标是把 250 条装备领域候选文本和机器提案整理成可人工审核、可双人一致性评估、可裁决、可冻结为后续实验数据集的材料。

这一步不是训练模型，也不是 P3/P4/P5 主实验；它是在为后面的自建装备领域数据集打基础。

## 2. 输入依据

人工标注必须依据以下文件：

1. `backups/P2/p2_review_sheet_llm_250_v3_schema_reparse.csv`
   - 当前可用的 250 条机器提案审阅表。
   - 其中 `NOT_STARTED=243`，`LLM_FAILED=7`。
   - `LLM_FAILED` 表示 LLM 提案不可用，人工应从原文空白开始标注。

2. `configs/p2_schema_draft_v3.yaml`
   - 当前人工标注采用的 schema。
   - 实体类型：`EQUIPMENT`、`MODULE`、`TECH_SCHEME`、`METRIC`。
   - 关系类型：`USES`、`HAS_METRIC`、`PART_OF`。

3. `configs/p2_llm_prompt_v6.yaml`
   - 未来如需重新生成 LLM 提案时采用的 prompt 规则。
   - 人工标注时不直接填写 prompt，但其中的边界规则与标注规范一致。

4. `docs/P2_ANNOTATION_GUIDE_DRAFT.md`
   - 人工标注的详细规则来源。
   - 已加入 v2 审阅抽查后的补充规则。

5. `docs/P2_REVIEW_AUDIT_FIXES_20260721.md`
   - 记录为什么从 v2 修到 v3。
   - 说明关系矩阵放宽、边界规则修订、`LLM_FAILED` 的处理原则。

6. `docs/问题建议1.md`
   - 人工抽查 v2 review CSV 后提出的问题和建议。
   - 是本轮 v3 精修的原始依据。

## 3. 人工标注要做什么

人工标注分三层：

1. annotator A 独立标注
   - 对指定文本填写实体和关系。
   - 不参考 annotator B 的结果。

2. annotator B 独立标注
   - 对同一批一致性样本独立填写实体和关系。
   - 不参考 annotator A 的结果。

3. adjudication 裁决
   - 对 A/B 不一致的样本进行最终裁决。
   - 裁决结果作为后续 support/dev/test 数据集的候选 gold 标注。

## 4. 标注内容

每条文本需要标注：

1. 实体
   - `start`：Python 字符偏移起点。
   - `end`：Python 字符偏移终点，右开区间。
   - `type`：实体类型。
   - `span`：原文连续片段，必须满足 `text[start:end] == span`。

2. 关系
   - `head`：头实体编号。
   - `tail`：尾实体编号。
   - `type`：关系类型。

关系必须只标同一句内显式支持的关系，不做常识补全、跨句共指、反向推断或传递推断。

## 5. 关键标注规则

1. `EQUIPMENT`
   - 可独立承担功能的装备、平台、系统、装置、武器或明确型号。
   - 组织、国家、军队、地点、部署方式不标为 `EQUIPMENT`。

2. `MODULE`
   - 当前语境中作为组成部分的子系统、组件、部件、载荷、战斗部、炸药、炮、发射架等。
   - 含数字的武器组件仍按组件标为 `MODULE`，不因含数字而标为 `METRIC`。

3. `TECH_SCHEME`
   - 非物理技术方法、体系、工作体制、算法、流程、信息状态、参数概念或能力概念。

4. `METRIC`
   - 可度量技术规格或参数值，例如射程、重量、口径、频率、速度、精度、阈值、温度范围。
   - 产品名、组件名、型号名中含数字，不自动标为 `METRIC`。

5. `PART_OF`
   - 方向固定为“小的组成部分 -> 大的整体”。
   - 例如 `炮管 PART_OF 坦克` 可以成立，`坦克 PART_OF 炮管` 不成立。

6. `USES`
   - 表示 head 明确使用、采用、挂载、携带、部署或依赖 tail 完成功能。
   - 不把“被控制、被调度、被服务”的语义反向写成 `USES`。

7. `HAS_METRIC`
   - 表示 tail 明确描述 head 的规格、能力、参数概念或可度量技术属性。

## 6. 对机器提案的使用方式

机器提案只是辅助建议，不是 gold 标注。

1. `human_review_status=NOT_STARTED`
   - 可以参考 LLM 和 distant supervision 提案。
   - 人工必须逐项检查 span、type、relation 方向和是否有遗漏。

2. `human_review_status=LLM_FAILED`
   - 不参考 LLM 提案。
   - 直接从原文空白开始标注。
   - 这类行不是负样本，也不能删除。

3. 机器建议和人工判断冲突时
   - 以人工标注规范为准。
   - 在 notes 中简短说明冲突类型，例如 `TYPE`、`BOUNDARY`、`RELATION_DIRECTION`、`OUT_OF_SCHEMA`。

## 7. 本步骤需要生成什么

人工标注准备完成后，应生成以下材料：

1. `data/annotation/annotator_a_250.csv`
   - 给 annotator A 使用。
   - 包含文本、来源、机器建议、A 的空白填写字段。

2. `data/annotation/annotator_b_100.csv`
   - 给 annotator B 使用。
   - 至少包含 100 条一致性样本。
   - B 的填写字段独立于 A。

3. `data/annotation/agreement_sample_ids.json`
   - 记录 100 条双人一致性样本的 ID。
   - 用于后续复算 agreement。

4. `data/annotation/adjudication_sheet.csv`
   - A/B 标注完成后生成。
   - 用于裁决不一致样本。

5. `logs/p2_annotation_prep_manifest.json`
   - 记录输入文件、输出文件、样本数、哈希、生成时间。

注意：这些文件名是建议的目标路径；正式生成前仍需确认当前仓库的数据目录策略，避免把不该进 Git 的数据提交到仓库。

## 8. 后续用于什么实验

人工标注结果用于完成 P2 Gate 2，并支撑后续所有领域实验。

1. 双人一致性评估
   - 使用 100 条双人独立标注样本。
   - 计算实体级 exact span + type micro-F1。
   - 必须达到 `>= 0.80`。

2. 裁决 gold 数据
   - A/B 不一致处经过 adjudication 得到最终 gold。

3. 切分自建领域数据集
   - 生成 `domain_support.jsonl`、`domain_dev.jsonl`、`domain_test.jsonl`。
   - 目标规模：support 30，dev 50，test 至少 100。

4. 冻结数据
   - 去重后写入 `FROZEN` 标记。
   - 记录所有文件哈希。
   - 冻结后不得根据 test 结果修改 prompt、阈值、schema、词表或 RAG 设置。

5. 支撑 P3/P4/P5
   - P3：few-shot 基础抽取，support 作为示例池，dev 做调试。
   - P4：RAG、词表和自验证模块调试，不能泄漏 test。
   - P5：完整 ablation matrix，在冻结 test 上最终评估。

## 9. 当前下一步

当前建议的下一步是：在不使用 GPU 的情况下，生成 annotator A/B 用的标注表和 100 条一致性样本 ID。

执行前需要项目负责人明确批准：

1. 是否允许开始“人工标注准备”。
2. 是否采用当前 250 条 v3 review sheet 作为标注来源。
3. 100 条一致性样本是否从 250 条中按固定 seed 抽取。

未经批准，不进入人工标注、数据切分、数据冻结、P3/P4/P5 或 400 条扩展运行。

## 10. 2026-07-21 补充规则：EQUIPMENT→EQUIPMENT 的 USES/PART_OF 裁决

当 head 和 tail 都是 `EQUIPMENT` 时，必须区分“搭载关系”和“组成关系”：

1. 原文出现 `搭载`、`部署`、`挂载`、`装备`、`配装`、`携带`、`装载`、`加装` 等搭载性语言时，关系标为 `USES`。
2. 原文出现 `组成`、`包括`、`包含`、`构成`、`是...的一部分`、`归属`、`隶属`、`下辖`、`由...组成` 等组成性语言时，关系标为 `PART_OF`。
3. 未显式描述时，不凭常识把“导弹装在飞机上”推成 `PART_OF`；需要时在裁决表中标记为不确定。
4. 该规则用于 adjudication 阶段统一修正 A/B 不一致和 LLM 过度 `PART_OF` 的问题，无需整体重标。
