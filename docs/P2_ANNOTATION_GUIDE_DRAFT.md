# P2 装备领域标注规范草案

状态：`P2 Pause A - 已由项目负责人审批（2026-07-16）`

版本：`p2-schema-draft-v1`

配套机器可读文件：`configs/p2_schema_draft.yaml`、`docs/p2_schema_examples_draft.jsonl`

本文定义已审批的 schema 和标注规则。十个示例均为合成文本，不来自
`domain_candidates.jsonl`。当前仅授权对真实候选执行确定性远程监督预标注并
生成未开始人工审阅的表格；LLM 标注和人工标注仍未获授权。

## 1. 标注目标

从每段公开装备领域文本中抽取实体和显式关系，并统一保存为：

```json
{"id":"...","text":"...","entities":[{"start":0,"end":4,"type":"EQUIPMENT","span":"..."}],"relations":[{"head":0,"tail":1,"type":"USES"}]}
```

- `start`、`end` 是 Python 字符偏移，`end` 不包含在实体内。
- 必须满足 `text[start:end] == span`。
- 实体按 `(start, end, type)` 排序；关系的 `head`、`tail` 引用排序后的实体下标。
- 不改写原文，不纠正错别字，不将别名统一成规范名。

## 2. 实体类型

### `EQUIPMENT`（装备）

可独立承担功能的装备、平台、系统、装置、武器或明确型号。例如无人机、导弹、
雷达、声呐、通信终端和指挥系统。型号前缀属于实体边界。

不标：泛指类别、代词（如“该系统”）、只表示用途的普通名词。相同词面在当前
语境中若明确作为更大装备的非独立组成部分，则标为 `MODULE`。

### `MODULE`（模块）

在当前语境中明确充当组成部分的物理或功能子系统、组件、单元、载荷或部件。
实体边界包含区分该模块所需的修饰语，例如“信号处理模块”。

不标：材料、人员、组织、地点，以及仅表示功能动作的普通动词。

### `TECH_SCHEME`（技术方案）

非物理的技术方法、体系结构、工作体制、算法、流程或工程方案，例如“惯性导航”
和“脉冲压缩技术”。

不标：孤立的“控制”“通信”“导航”等泛化动作；普通工作模式只有在构成明确的
命名技术方案时才单独标注。

### `METRIC`（指标）

能够独立表达技术规格的连续短语，通常包含指标名称，以及数值、范围、阈值、
等级或必要的局部工况。比较词、上下限、单位和改变含义的紧邻工况一并纳入。

不标：型号数字、年份、序号、普通计数、没有指标名称的孤立数字，以及“性能好”
一类无法复算的模糊描述。

## 3. 关系类型与方向

| 关系 | 允许的 head | 允许的 tail | 判定规则 |
| --- | --- | --- | --- |
| `USES` | `EQUIPMENT` / `MODULE` | `MODULE` / `TECH_SCHEME` | 原文明示“采用、使用、利用”等功能使用关系 |
| `HAS_METRIC` | `EQUIPMENT` / `MODULE` | `METRIC` | 指标在原文中明确描述该装备或模块 |
| `PART_OF` | `MODULE` | `EQUIPMENT` / `MODULE` | 方向固定为“部分 -> 整体”，原文明示组成、包含或安装关系 |

“使用”不自动推出“组成”，“组成”也不自动生成反向 `USES`。只有原文分别明示时，
才可同时标两个关系。

## 4. 边界与一致性规则

1. 选择“最短但语义自足”的连续 span；型号、关键限定词和必要工况保留，外围介词、
   所有格助词和句末标点排除。
2. 默认禁止嵌套或重叠实体。一个长名称内部出现短名称时，只保留语义完整的最长
   名称；协调并列项则分别标注。
3. 同一实体在文本中重复出现时，每个显式词面分别标注；代词和省略成分不标。
4. v1 关系只允许同一句内、两个显式实体词面之间的关系。不通过“它、该平台”等
   代词建立关系，不做跨句共指。
5. 不使用领域常识补关系，不生成逆关系或传递关系。例如 `A PART_OF B` 和
   `B PART_OF C` 不能推出 `A PART_OF C`。
6. 否定、假设、疑问或未证实引述中的实体仍按词面标注，但不建立被否定或假设的
   关系。数值上下限（如“不低于”）是指标约束，不属于否定关系。
7. 无法稳定判断的项目不得猜测。在审阅表中使用 `BOUNDARY`、`TYPE`、
   `RELATION`、`COREFERENCE`、`NEGATION` 或 `OTHER` 标记，交由裁决。

## 5. 十个合成标注示例

完整偏移和关系索引见 `docs/p2_schema_examples_draft.jsonl`。

| # | 文本 | 核心判定 |
| ---: | --- | --- |
| 1 | 苍穹-1无人机采用卫星导航技术。 | 型号整体为装备；装备 `USES` 技术方案 |
| 2 | 海岳雷达的信号处理模块采用脉冲压缩技术。 | 模块 `PART_OF` 装备；模块 `USES` 技术方案 |
| 3 | 远航导弹的制导单元采用惯性导航。 | 同时覆盖组成关系和技术采用关系 |
| 4 | 星盾雷达最大探测距离不低于200公里。 | 指标保留名称、阈值词、数值和单位 |
| 5 | 云帆通信终端工作频段2.4至2.5吉赫。 | 范围与单位属于完整指标 |
| 6 | 雷霆车载系统使用搜索雷达模块和跟踪雷达模块。 | `USES` 可指向模块，但不由此推断 `PART_OF` |
| 7 | 北辰-3雷达于2024年完成测试，编号3和年份2024均不是性能指标。 | 型号中的 3 和年份均不标为指标 |
| 8 | 玄武发动机安装在天舟平台上，该平台采用液体推进技术。 | 标组成关系；不通过“该平台”建立 `USES` |
| 9 | 试验验证了X波段有源相控阵雷达的稳定性。 | 只保留完整长名称，不嵌套标短名称 |
| 10 | 海星声呐在浅水模式下的定位误差小于5米。 | 改变指标含义的紧邻工况纳入指标 span |

## 6. 人工标注与一致性协议

1. schema 获批后才允许对真实候选生成远程监督建议；14B 辅助标注仍需单独的
   付费 GPU 批准。
2. 建议层、人工 A 层、人工 B 层和最终裁决层分别保存，任何一层都不得覆盖另一层。
3. 一致性抽样的 100 段由两位标注者独立从空白文本标注，不展示对方结果；为避免
   共享机器建议虚增一致性，建议不向这 100 段的两位标注者展示 LLM 建议。
4. 主门指标为实体 `(start, end, type)` 完全匹配的 micro-F1，必须至少为 `0.80`。
   关系 `(head_span, relation_type, tail_span)` 完全匹配 F1 同时报告，但本阶段不自行
   增设通过阈值。
5. 低于 `0.80` 时停止，汇总边界、类型和关系混淆，修订规范后重新独立标注；不得
   直接进入数据冻结或后续实验。
6. 裁决完成后才划分 support 30、dev 50、test 至少 100；随后执行固定 8-gram
   去重、写入 `logs/dedup.json`、创建 `FROZEN` 并记录全部哈希。

## 7. 已审批的决定

1. 四类实体定义及“同一词面按当前结构角色区分 EQUIPMENT/MODULE”。
2. `METRIC` 使用“指标名 + 值/范围/阈值/单位 + 必要紧邻工况”的完整 span。
3. 三类关系的允许类型矩阵，尤其是 `USES` 是否允许 tail 为 `MODULE`。
4. v1 禁止重叠实体、跨句关系和代词共指关系。
5. 100 段一致性样本采用不展示 LLM 建议的独立空白标注。

的审阅表导出；不得执行人工标注、14B 推理或任何付费 GPU 工作。
