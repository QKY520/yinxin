## 1. 输出与硬约束

每行填写 JSON 数组：

```json
[{"start":0,"end":4,"type":"EQUIPMENT","span":"示例装备"}]
```

必须同时满足：

1. offset 使用 Python 字符位置，`end` 不包含，且 `text[start:end] == span`；
2. 合法类型仅为 `EQUIPMENT`、`MODULE`、`TECH_SCHEME`、`METRIC`；
3. 每个实体只有一个类型，不允许嵌套或重叠；
4. 按 `(start,end,type)` 升序排列；
5. 同一合格 mention 每次明确出现都分别标注；
6. 无实体时填写 `[]`，不得留空；
7. 不查看另一标注者结果、旧 gold、模型预测或机器建议。

## 2. 什么内容进入本 schema

只标“文本中明确出现、语义自足、并在当前语境中被实例化”的以下内容：

- 可独立承担功能的装备、平台、系统、装置、武器或具体设计；
- 明确作为组成部分的子系统、组件、单元、载荷或结构/功能部件；
- 非物理且可命名的技术、方法、算法、体制、流程或工程方案；
- 能独立表达技术规格的指标短语。

“实例化”不要求必须有型号。专利文本中的“本发明一种无人飞行器”及其明确组成
清单，属于该段正在描述的具体设计，可以标注。以下内容默认不标：

- 只用于类别罗列、攻击目标、能力对象或比较背景的泛指名词；
- 人员、组织、国家、地点、时间、事件和合同金额；
- 普通信号、数据、状态、能力、动作和目的描述；
- 原材料本身，除非它在语境中是明确的装药、载荷或功能组件；
- 没有属性头的普通数字、年份、数量和型号内部数字。

## 3. 固定决策树

对每个候选短语依次判断：

1. **是否为合格 mention**：明确出现、语义自足、当前语境已实例化；否则不标。
2. **是否为技术规格**：属性头与数值、范围、阈值、等级或单位构成连续自足短语；
   是则标 `METRIC`。
3. **对象还是方法**：
   - 可安装、部署、组成、承载或承担功能的系统/装置/部件属于对象；
   - 非物理方法、算法、体制、流程或工程方案属于 `TECH_SCHEME`。
4. **完整对象还是组成部分**：
   - 当前段把对象作为独立整体或完整任务系统，标 `EQUIPMENT`；
   - 当前段明确它是某整体的组成、安装件、载荷、机载设备或子系统，标 `MODULE`。
5. **仍不确定**：给出当前最佳判断，并使用一次相应疑点码；不得跳过整类。

词尾不能单独决定类型。“系统”可能是完整 `EQUIPMENT`，也可能是机内 `MODULE`；
只有当它指非物理方法体系时才是 `TECH_SCHEME`。

## 4. 四类实体

### 4.1 `EQUIPMENT`

完整或可独立承担任务/功能的装备、平台、整机、武器、装置、部署系统、软件/功能
平台或明确型号。

典型：完整武器系统、无人机、导弹、独立雷达、通信终端、自动指挥系统。

判定要点：

- “被某方法使用/控制/观测”不使其自动变成 `MODULE`；
- 无明确更大整体和组成证据时，独立装置按 `EQUIPMENT`；
- “密集阵-海拉姆系统”“宙斯盾武器系统”等物理/功能系统不能标成
  `TECH_SCHEME`；
- 型号、系列名和紧邻装备类别头属于同一边界。

### 4.2 `MODULE`

在当前语境中明确充当组成部分的物理或功能子系统、组件、单元、载荷、弹药、装药、
结构件或部件。

强组成信号：

- “由/包括/包含/组成”“X 的 Y”“安装/加装/配备 Y”；
- “机载/舰载 Y”“Y 作为载荷/子系统/组件”；
- 名称本身明确为“模块、组件、部件、单元、引信、战斗部、发射装置”等。

限制：

- “X 的 Y”只有在 X 是技术整体且 Y 为其组成时才成立；组织所有关系不算；
- 参与某种方法、被控制或被使用不等于组成；
- 原材料不标，但“90g B炸药”若明确作为装药/功能组件则标 `MODULE`；
- 已在段内明确为机载/舰载部件的同一指称，其无歧义缩写继续标 `MODULE`。

### 4.3 `TECH_SCHEME`

非物理、可命名的技术方法、算法、工作体制、体系结构、流程、控制律或工程方案。
它回答“采用什么方法/机制”，不是“安装了什么对象”。

标注：

- “脉冲压缩技术”“被动红外制导”“自适应波束形成算法”；
- 明确命名的控制律、工作体制或工程方法。

不标：

- 雷达、装置、终端、发射器、可部署系统等对象；
- “电子战支援”“探测能力”等能力或支援描述；
- “卫星导航信号”等信息对象；
- 孤立的“控制、通信、导航、探测”等普通动作。

### 4.4 `METRIC`

能够独立表达技术规格的连续短语。边界包括属性头、比较词/上下限、数值、单位和改变
指标含义的紧邻工况。

标注：

- `有效载荷200公斤`；
- `重21千克`；
- `超过70千米的距离`；
- `15.24千米的高度`；
- `150千米范围`。

不标：年份、序号、普通计数、型号数字、合同金额、没有属性含义的孤立数字。

## 5. `EQUIPMENT / MODULE / TECH_SCHEME` 最小对照

| 表达与语境 | 类型 | 原因 |
| --- | --- | --- |
| 摄像装置被用户启动，无更大整体组成证据 | `EQUIPMENT` | 独立装置 |
| F-35 机载 AN/AAQ-37 分布式孔径系统 | `MODULE` | 明确机载子系统 |
| 后文无歧义缩写 DAS 指上述机载系统 | `MODULE` | 同一指称继承结构角色 |
| 宙斯盾武器系统作为舰上完整武器系统 | `EQUIPMENT` | 完整任务系统，不是方法 |
| RAM发射装置配装于更大武器系统 | `MODULE` | 明确组成部分 |
| 冲击板组件包括冲击板与传感器装置 | `MODULE` | “组件”及组成语境 |
| 导航系统本身包括处理器模块 | `EQUIPMENT` | 它是所列模块的整体 |
| 北斗导航方法/惯性导航技术 | `TECH_SCHEME` | 非物理方法 |

以上是 v4 规则示例，不是对首轮 24 条进行 gold 裁决或重新计分。

## 6. 边界优先级

按以下顺序确定连续 span：

1. 保留型号/系列标识与紧邻类别头，如 `KAB-50S卫星制导炸弹`、
   `彩虹系列无人机`；
2. 保留改变身份或技术含义的必要限定词，如 `基型BAT子弹药`、
   `计算机控制雷达制导20毫米火炮系统`；
3. 排除外围介词、所有格助词、连接词、谓词、评价性修饰语和句末标点；
4. 指标保留连续属性头，即使属性头位于数值之后，如“70千米的距离”；
5. 一个长名称内部含短名称时，在该出现位置只标完整自足外层，不嵌套标内层；
6. 内层部件在后文作为独立连续词面再次出现时，再单独标注。

共享中心词并列：若两个并列修饰项共享一个中心词，无法在原文中拆成两个连续、
非重叠、语义完整的 mention，则标一个完整并列短语。例如：

```text
被动式声学和红外敏感器
```

不得补写原文不存在的“敏感器”，也不得只截取后一个并列项作为对整个结构的替代。

## 7. 重复 mention、缩写和回指

1. 每个已标 span 必须全文搜索相同词面；每次合格的明确出现分别标注。
2. 型号、名称和无歧义缩写指向同一对象时，沿用该对象在当前段已明确的结构角色。
3. “该/所述/这种”不进入实体 span。
4. 去掉指示词后，若剩余词面仍为具体型号、名称或语义自足技术名词，例如
   “智能终端”“冲击板”“DAS”，则照常标注。
5. 若剩余词面只有无区分信息的“系统、装置、设备、平台、模块”等泛化回指，则不标。
6. 不通过回指新建关系；本条只用于保持 NER mention 类型一致。

## 8. 提交前单表 preflight

每位标注者只检查自己的文件，并在交回协调员、锁定 SHA256 前完成：

1. JSON 可解析，字段完整，offset 为整数，span 与文本一致；
2. 类型合法，无重复、嵌套、重叠，实体已排序；
3. 每个已标词面其他出现位置均已逐项确认；
4. 零实体为 `[]`；
5. 疑点码合法且去重，同一码每行最多一次；
6. preflight 不读取另一标注者、旧 gold、预测、模型建议或 coordinator map。

协调员只能退回问题及位置，不能代替标注者排序、补标签或修改类型。结构修复完成后
再锁定提交哈希。

## 9. 疑点码

可用值保持不变；多个值用分号分隔且不得重复：

- `TYPE_EQUIPMENT_MODULE`
- `TYPE_PHYSICAL_TECH`
- `BOUNDARY`
- `METRIC_SCOPE`
- `REPEATED_MENTION`
- `EXCLUDE_OR_TAG`
- `OTHER`

疑点码不替代当前最佳标签，也不能作为整类跳过的理由。
