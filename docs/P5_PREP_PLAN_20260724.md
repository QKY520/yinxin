# P5 Prep Plan - 2026-07-24

## Scope

This document freezes the pre-P5 decision after the P3 domain-dev gate audit.
It is a GPU-free planning artifact only. It does not authorize paid GPU runs,
does not use `domain_test`, and does not change prompts, glossary entries, RAG
settings, or verifier wording based on test results.

Current gate decision: P3 -> P5 gate passed for planning. The six-row dev
matrix is accepted as a sanity-stage decision record: A is a usable baseline,
B is negative, C is mixed, D(RAG) is the current best positive result, and
verification E v1/v2 is negative or near-tie negative because it over-deletes
correct entities. The next step is P5 configuration freeze, not immediate P5
execution.

## P3 Evidence Accepted For Gate

The P3 `domain_dev50`, K=5, seed 42 sanity results are not final paper numbers,
but they are sufficient for P5 planning. D(RAG) improved over C with F1
`0.5415` vs `0.5097`, FP `159` vs `190`, and hallucination rate `0.4789` vs
`0.5278`. D also beat A on this dev sanity by F1 `+0.0193` and FP `177 -> 159`.
The human D audit judged it acceptable positive despite noisy retrieval because
the main observed effect was more conservative output and fewer over-labeled
entities. E v1 and E v2 are not accepted as positive because they deleted too
many correct entities; E v3 remains only a GPU-free design artifact.

## Config Freeze Requirements

Before any paid P5 run, the agent must prepare config drafts and stop for human
approval. The config review must confirm these points:

1. kNN demonstration pool is support only.
2. RAG corpus excludes held-out evaluation IDs. For final domain P5, exclude
   `domain_test` IDs from retrieval and never retrieve the query itself.
3. `domain_test` is not opened for prompt, glossary, RAG, threshold, or verifier
   tuning.
4. A/B/C/D differ by only the intended ablation switch:
   A fixed random only; B kNN only; C B plus glossary; D C plus RAG.
5. K and seed are explicit in every YAML.
6. Every run writes per-query rows with `id`, `dataset`, `config`, `k`, `seed`,
   `gold`, `pred_raw`, `pred_verified`, `latency_ms`, `parse_failure`,
   `raw_llm_output_hash`, and `prompt_hash`.
7. Metrics are recomputable from per-query JSONL.
8. No E/E-prime config is included in paid execution unless separately approved.

## Run Order

### M0 - GPU-Free Config Freeze

Agent action: create P5 config drafts, verify config hashes, verify output paths,
and prepare a run manifest. This stage may use AutoDL GPU-free shell for
lightweight checks, but no model calls.

Human action: review the P5 manifest and approve exactly one bounded paid gate.

Decision gate: proceed only if configs match the frozen matrix and leakage
guards are explicit.

### M1 - Paid Domain Pilot

Recommended first paid gate: domain-only A/B/C/D, K=5, seed 42. This is a
bounded pilot to verify that final-grid commands, paths, cache, RAG exclusion,
and metrics work before running all seeds.

Stop condition: after the pilot, stop vLLM, verify GPU memory returns to 0 MiB,
back up artifacts, sync lightweight outputs, report cost, and wait.

### M2 - Domain Main Grid

Run domain A/B/C/D, K=5, seeds 42/43/44. If M1 seed 42 is valid and unchanged,
reuse it rather than rerun it.

Decision gate: continue only if per-query rows reload and aggregate metrics
recompute exactly.

### M3 - Domain K-Scan

Run domain A and D at K=1 and K=10 for seeds 42/43/44. K=5 comes from M2.

Purpose: show whether the RAG gain is robust to support-shot budget.

### M4 - CLUENER Protocol Confirmation And Runs

Before CLUENER paid execution, confirm which gold-bearing split is valid for
offline metrics. Public unlabeled test files must not be treated as all-negative
gold. If the protocol is confirmed, run A/B/C/D at K=5 and optionally A/D
K-scan.

### M5 - Optional Negative Verification Row

Run only after A/B/C/D are complete and only with explicit approval. The
recommended default is to skip this stage and preserve P3 E v1/v2 as dev
negative evidence.

## Outputs Expected From P5

P5 must produce:

- per-query JSONL for every `(dataset, config, k, seed)`;
- `results/main_table.csv` with one row per completed cell;
- `results/summary.md` with mean and standard deviation over seeds;
- entity-level precision, recall, F1, and hallucination rate;
- exact relation triple metrics for domain rows where supported;
- parse-failure rate and latency summaries;
- F1-vs-K plot for A and D;
- hallucination comparison plot for A/B/C/D;
- backup manifest and hash verification.

## Human Audit After P5

After P5 finishes, human audit should not review every row. It should focus on:

1. whether D remains better than C and A on frozen evaluation;
2. whether D's FP reduction is still real under three seeds;
3. whether B/C negative or mixed behavior is stable enough to report;
4. whether any CLUENER result conflicts with the domain story;
5. whether RE is strong enough to include in the main paper or should remain
   auxiliary/appendix evidence;
6. whether any optional verification row is necessary for the paper narrative.
