## 4. 标注流程

### 4.1 Annotator A（全量 250 条）

1. 打开 `data/annotation/annotator_a_250.csv`
2. 对每条记录：
   - 阅读 `text_display`
   - 参考 `union_entities_json` 和 `union_relations_json`（机器建议）
   - 填写 `annotator_a_entities_json`、`annotator_a_relations_json`
   - 如有冲突/不确定，在 `annotator_a_notes` 中注明类型：`TYPE` / `BOUNDARY` / `RELATION_DIRECTION` / `OUT_OF_SCHEMA` / `MISSING`
3. 对 `LLM_FAILED` 行（7 条），不参考机器建议，从零标注

### 4.2 Annotator B（一致性样本 100 条）

1. 打开 `data/annotation/annotator_b_100.csv`
2. 独立标注，不参考 A 的结果
3. 标注方式同 A

### 4.3 标注规则速查

| 规则 | 说明 |
|------|------|
| 实体类型 | `EQUIPMENT` / `MODULE` / `TECH_SCHEME` / `METRIC` |
| 关系类型 | `USES` / `HAS_METRIC` / `PART_OF` |
| 偏移量 | Python 字符偏移，`end` 为右开区间 |
| span 验证 | `text[start:end] == span` 必须成立 |
| 关系范围 | 仅限同一句内显式支持的关系 |
| 组织/地点 | 不标注（ORGANIZATION / LOCATION 不在 schema 中） |
| 含数值的组件 | 标注为 MODULE，不是 METRIC（如 "90g B炸药" → MODULE） |
| PART_OF 方向 | 小组件 → 大整体（"炮管 PART_OF 坦克"✓，"坦克 PART_OF 炮管"✗） |
| USES 方向 | head 使用/搭载/挂载/部署/依赖 tail |
| 冲突标注 | 在 notes 中写 `TYPE` / `BOUNDARY` / `RELATION_DIRECTION` / `OUT_OF_SCHEMA` / `MISSING` |

完整规则见 `docs/P2_ANNOTATION_GUIDE_DRAFT.md`。

## 5. 标注完成后流程

### 5.1 一致性评估

在 100 条双人标注样本上计算：

- **主指标**：实体级 exact span + type micro-F1
- **阈值**：≥ 0.80 方可进入下一步
- **辅助指标**：关系 exact-triple micro-F1（报告但不作为 gate）

### 5.2 裁决（adjudication）

对 A/B 不一致的样本：
1. 将 A/B 结果填入 `adjudication_sheet.csv`
2. 逐条裁决，填写 `adjudicated_entities_json` + `adjudicated_relations_json`
3. 裁决依据标注规范，不偏向任一 annotator

### 5.3 数据切分

裁决后的 gold 数据切分为：

| split | 目标数量 | 用途 |
|-------|----------|------|
| support | 30 | kNN 示例池、few-shot 演示 |
| dev | 50 | prompt 调优、阈值选择 |
| test | ≥100 | 最终评估，冻结后不可修改 |

### 5.4 数据冻结

1. 切分完成后创建 `data/FROZEN` 标记文件
2. 记录所有分片的 SHA256 哈希
3. 冻结后不得根据 test 结果修改 prompt、阈值、schema、词表或 RAG 设置
