## 详细分析

### 1. domain-candidate-0039 — 视觉检测系统摊铺机（关系结构错误）

**严重程度**：🔴 高
**类别**：PART_OF 关系附属错误
**attempts**：2 次（第 1 次 type matrix violation，第 2 次通过）

**原文关键句**：

> 升降机上设有第一升降杆和第二升降杆，第一升降杆上设有连杆，连杆的底部连接有滚筒外壳，滚筒外壳内设有滚筒，滚筒外壳上设有振动棒和图像传感器，第二升降杆的底部设有刮板

**LLM 输出（错误）**：

| 关系 | LLM 认为 | 实际应为 |
|------|----------|----------|
| 连杆 PART_OF ? | 第二升降杆 | **第一升降杆** |
| 滚筒外壳 PART_OF ? | 第二升降杆 | **第一升降杆**（通过连杆） |
| 振动棒 PART_OF ? | 第二升降杆 | **第一升降杆**（通过滚筒外壳→连杆链） |
| 刮板 PART_OF ? | 升降机 | **第二升降杆** |

**根因推测**：中文长句中 "第一升降杆上设有…第二升降杆的底部设有…" 的远距离依存关系解析失败。LLM 把后半句所有具体组件都挂到了最后提到的 "第二升降杆" 上，而刮板则被上浮到了父级（升降机）。

**影响范围**：复杂嵌套结构的专利文本容易出现同类错误。

### 2. domain-candidate-0099 — 海拉姆反舰导弹防御系统（Schema 约束过严）

**严重程度**：🟡 中
**类别**：Schema type matrix 限制导致关系丢失
**attempts**：2 次（第 1 次 type matrix violation，第 2 次清空所有关系）

**LLM 实体输出**（正确）：

```
海拉姆反舰导弹防御系统  EQUIPMENT
独立号近海战斗舰        EQUIPMENT
海拉姆导弹              EQUIPMENT
独立号作战管理系统      EQUIPMENT
```

**LLM 关系输出**：空（第 2 次尝试全部丢弃）

**第 1 次尝试错误信息**：`relation 0 violates the PART_OF type matrix`

**问题**：LLM 第 1 次尝试可能想输出 `海拉姆导弹 PART_OF 海拉姆反舰导弹防御系统`，但两者都是 EQUIPMENT 类型，当前 type matrix 不允许 EQUIPMENT→EQUIPMENT 的 PART_OF。第 2 次尝试直接放弃所有关系。

**修复建议**：
- 放宽 PART_OF type matrix，允许 EQUIPMENT→EQUIPMENT（导弹是防御系统的组成部分）
- 或引入新的 relation type 如 `HAS_COMPONENT` / `BELONGS_TO`

### 3. domain-candidate-0015 — 无人飞行器虚拟观光系统（USES 方向存疑）

**严重程度**：🟡 中
**类别**：关系语义方向问题

**LLM 输出**：

```
无人飞行器 EQUIPMENT  USES  操作子系统 MODULE
无人飞行器 EQUIPMENT  USES  终端子系统 MODULE
```

**原文**：

> 操作子系统用于响应观光请求，分派一个或多个无人飞行器至兴趣观光区域
> 终端子系统用于输入观光请求，以及呈现获取的兴趣观光区域的相关数据

**问题**：原文明确是子系统操控/调度无人机，而非无人机使用子系统。USES 的方向反了。正确的理解应该是子系统操控无人机，或者无人机是被操作子系统调度的对象。

**根因推测**：`USES` 在当前 prompt 中的语义不够精确。LLM 可能将 USES 理解为 "与…相关"或"在系统中与…配合"，而非严格的功能使用关系。

**修复建议**：在 prompt 中明确定义 USES 的语义方向——主语是使用者/搭载平台/主动方，宾语是被使用/被搭载/被动方。或引入新 relation `CONTROLS` / `IS_CONTROLLED_BY`。

### 4. domain-candidate-0028 — test-518（数据质量问题）

**严重程度**：🟢 低
**类别**：输入数据质量

**文本内容**（已损坏）：

> 400一种无人机的控制方法和无人机的控制设接收终端设备发送的服务请求消息，该服务请求410410备，可以实现对无人机的合法化控制操作…

**LLM 输出**：空实体、空关系（latency 1001ms，远低于正常的 8-50s）

**评价**：LLM 对垃圾输入的处理是正确的——不应强行抽取。但 `source_id: test-518` 表明这是测试数据，却混入了 sanity 样本。全量 400 条中如果存在类似损坏文本，既浪费 GPU 又无产出。

**修复建议**：在运行全量之前增加预处理过滤器——检测连续数字嵌入、重复片段、过短/过长文本等。

## 附带观察（非错误，但值得注意）

### A. Distant supervision 几乎无贡献

10 条中：
- 7 条 distant 为空
- 2 条 distant 只提供了实体名称的冗余重复标注（domain-candidate-0004 IS-2 标了 5 次同名实体）
- 1 条 distant 标注了比 LLM 更短的 span（domain-candidate-0006 AGM-154，0-16 vs LLM 0-22）

**结论**：当前 distant supervision 对这 10 条几乎没提供增量价值。全量 400 条如果类似，可以考虑降低 distant 权重或仅在 LLM 空输出时回退。

### B. 第 1 次尝试 parse error 率

10 条中有 2 条第 1 次尝试因 `PART_OF type matrix violation` 失败（domain-candidate-0039, domain-candidate-0099），但重试后都成功（0039 修复了 type error，0099 清空关系）。重试机制有效，但 type matrix violation 是系统性问题而非偶发。

### C. 无关系输出的比例

10 条中有 4 条关系为空：
- domain-candidate-0099（被 type matrix 压制）
- domain-candidate-0241（合理——并列列举，无结构关系）
- domain-candidate-0347（合理——装备清单，无关系）
- domain-candidate-0028（合理——垃圾文本）

其中 3 条是合理的空输出，1 条是被压制。这个比例在预期范围内。
