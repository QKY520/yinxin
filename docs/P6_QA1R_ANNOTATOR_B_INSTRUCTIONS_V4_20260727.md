## 3. 独立标注方法

标注者 B 必须独立审查并标注 B 表中的全部行，不与 A 分工，也不跳过难例。每行按
以下顺序判断：

1. 候选短语是否明确出现、语义自足并在当前语境中实例化；否则不标。
2. 若为完整技术规格短语，标为 `METRIC`。
3. 若为非物理方法、算法、体制、流程或工程方案，标为 `TECH_SCHEME`。
4. 若为物理或功能对象，根据当前语境中的结构角色选择：
   - 独立整体或可独立承担功能：`EQUIPMENT`；
   - 有组成、安装、机载、载荷或子系统证据：`MODULE`。
5. 按 v4 确定完整连续边界，再检查全文中同一词面和无歧义缩写的每次合格出现。

实体数组格式：

```json
[{"start":0,"end":4,"type":"EQUIPMENT","span":"示例装备"}]
```

必须保证 `text[start:end] == span`，`end` 不包含；实体按 `(start,end,type)` 升序，
不得重复、嵌套或重叠。无实体必须填写 `[]`，不能留空。

有疑问时仍要填写当前最佳标签，同时使用一个或多个合法疑点码：

- `TYPE_EQUIPMENT_MODULE`
- `TYPE_PHYSICAL_TECH`
- `BOUNDARY`
- `METRIC_SCOPE`
- `REPEATED_MENTION`
- `EXCLUDE_OR_TAG`
- `OTHER`

多个疑点码用分号分隔并去重。疑点码不能代替标签，也不能用来跳过整类实体。

## 4. B 的单表提交前检查

只能检查自己的 B 文件：

1. 每行 JSON 均可解析，offset、span 和 text 完全一致。

3. 对每个已标词面，已逐项检查其余出现位置，避免漏标重复 mention。
4. 所有行均已完成；零实体行是 `[]`，没有空字段。
5. 疑点码合法、去重，同一码在同一行最多出现一次。
6. 未打开或读取 A 文件、旧 gold、旧 24 条完成文件、预测、模型建议或 coordinator map。
